# PRD 生成器 Skill 使用说明

## 📖 简介

`prd` 是一个专门为 Yudao Cloud 项目设计的产品需求文档（PRD）自动生成工具。

它能够根据你提供的功能需求描述和 demo 效果，自动生成符合项目规范的完整 PRD 文档。

---

## 🚀 快速开始

### 基本用法

```
/prd <功能需求描述>
```

### 带参数用法

```
/prd <功能需求描述> --demo <demo地址或截图路径> --module <模块名称>
```

---

## 📋 使用示例

### 示例 1: 生成用户管理功能的 PRD

```
/prd 用户管理功能，包括用户列表展示、新增用户、编辑用户信息、删除用户、重置密码等功能
```

### 示例 2: 带 Demo 的订单管理 PRD

```
/prd 订单管理功能，需要支持订单列表搜索、查看订单详情、订单状态流转（待支付→已支付→已完成） --demo https://example.com/order-demo.png --module tz-module-pressure
```

### 示例 3: 设备管理完整功能

```
/prd 设备台账管理功能，包括设备信息录入、设备分类、设备状态管理、设备维护记录、设备报废处理，支持设备二维码生成 --demo C:\Users\Admin\Desktop\device-demo.png --module tz-module-pressure
```

## 📁 文档存储位置

生成的 PRD 文档会自动保存到：

```
.claude/PRD/[功能名称]_PRD_YYYYMMDD.md
```

例如：`报告修改功能PRD_20260312.md`

## 📄 生成的 PRD 包含内容

每个 PRD 文档包含以下 11 个主要章节：

1. **文档基础信息** - 版本、日期、优先级
2. **需求概述** - 背景、目标用户、功能目标
3. **功能详细说明** - 流程图、页面布局、交互说明、表单字段
4. **数据结构设计** - 数据库表设计、字段说明
5. **后端 VO 设计** - 请求/响应 VO 定义
6. **接口定义** - 完整的 REST API 接口清单和说明
7. **前端实现** - 页面文件结构、API 调用、路由配置
8. **权限标识** - 统一的权限字符串定义
9. **业务规则** - 数据权限、状态流转、业务约束
10. **非功能需求** - 性能、安全、兼容性要求
11. **测试要点 & 验收标准**

## 🎯 生成的文档特点

### 符合项目规范
- 遵循 Spring Boot + Vue3 技术栈
- 数据库字段使用下划线命名
- Java 字段使用驼峰命名
- 接口路径遵循 `/admin-api/{module}/{feature}/{action}` 格式

### 内容完整详细
- 包含前后端完整实现指南
- 提供 SQL 建表语句
- 提供 Java VO 代码示例
- 提供 TypeScript API 接口代码
- 定义权限字符串

### 可直接交付开发
- 开发人员可以直接根据 PRD 开始编码
- 减少需求沟通成本
- 统一文档格式，便于查阅和维护

## 🔧 参数说明

| 参数 | 说明 | 是否必需 | 默认值 |
|------|------|---------|--------|
| `requirement` | 功能需求描述 | ✅ 必需 | - |
| `--demo` | Demo 页面地址或截图路径 | ❌ 可选 | 无 |
| `--module` | 所属模块名称 | ❌ 可选 | 待定 |

### 支持的模块名称

- `tz-module-system` - 系统管理模块
- `tz-module-infra` - 基础设施模块
- `tz-module-bpm` - 工作流模块
- `tz-module-member` - 会员管理模块
- `tz-module-pressure` - 承压业务模块
- `tz-module-laboratory` - 实验室管理模块
- `tz-module-mp` - 微信公众号模块

## 💡 最佳实践

### 1. 需求描述要清晰详细

✅ 好的描述：
```
设备管理功能，包括设备台账录入、设备分类管理、设备状态（在用/维修/报废）、
设备维护记录、设备二维码生成、设备统计报表
```

❌ 不好的描述：
```
设备管理
```

### 2. 提供 Demo 截图

如果已经有 Demo 页面，提供截图可以：
- 自动提取页面布局信息
- 识别表单字段列表
- 分析交互逻辑
- 提高生成准确性

### 3. 明确所属模块

指定模块名称可以：
- 自动生成正确的接口路径
- 确定代码文件存放位置
- 匹配正确的权限前缀

## ❓ 常见问题

### Q: 生成的 PRD 可以修改吗？
A: 可以，PRD 是标准的 Markdown 文件，你可以直接编辑或要求 AI 修改特定章节。

### Q: 如何基于已有 PRD 进行迭代？
A: 可以告诉 AI："基于现有的 xxx PRD，增加 xxx 功能"

### Q: 支持多人协作吗？
A: PRD 文件可以提交到 Git 进行版本管理，支持团队协作。

### Q: 可以导出为 Word/PDF 吗？
A: Markdown 文件可以使用 Pandoc 等工具转换为 Word 或 PDF 格式。
