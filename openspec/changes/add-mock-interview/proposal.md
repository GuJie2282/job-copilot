# Proposal: 模拟面试（mock-interview）

## Why（为什么需要）

### 当前痛点
用户建立画像、匹配 JD 之后，面临的下一个陡坡是"面试本身"。三个具体痛点：

1. **不知道考什么**：JD 暗藏的考查点、目标公司的真实问法，用户两眼一抹黑；固定题库 App 的题目又与自身经历脱节。
2. **上考场就紧张**：缺少低成本、可重复的"预演"环境。真到面试时，紧张导致发挥失常，而紧张只能靠"多练真实场景"来脱敏。
3. **练了没反馈**：自己对着镜子练或找朋友练，得不到专业、结构化、可对照的复盘——亮点在哪、失分在哪、下次怎么改，全凭感觉。

### 产品价值
模拟面试是求职 Copilot MVP 闭环的**第四环**，也是**价值感知最强**的一环：

1. **承上**：消费前三环产出——画像让面试官"认识你"从而个性化追问，JD/Gap 让出题"定向"到岗位真实要求；**即使没有 JD，也能基于求职目标岗位 + 画像强弱项做通用练习**。
2. **启下**：每场面试的复盘沉淀进个人面经库，构成数据飞轮的起点——下次出题更懂你、复盘能看到成长曲线。
3. **核心体验**：从"做题"升级为"被追问"——真实面试的灵魂是**基于回答的动态深挖**，不是一份固定题单。能否高质量地追问，是模拟面试与题库 App 的分水岭。
4. **差异化**：实战/教练双模式 + 可配置人设（风格 × 角色）+ 个性化面经库，区别于市面上"固定题库 + 通用反馈"的单点工具。

### 战略定位
模拟面试是**用户停留时长**与**数据资产沉淀**的双重引擎。它既是闭环的高潮体验，又是面经库飞轮的启动器——用户每练一场，私有资产增厚一分，这是竞品抄不走的壁垒（对齐产品方案的"私有面经库 + 画像持续沉淀"差异化定位）。

## What Changes（做什么变更）

### 新增能力

1. **mock-interview（模拟面试）**
   - 面试会话创建与配置：题型（行为/技术/案例/动机/全流程/压力）、档位（简短/正常/深度/全程）、模式（实战/教练）、人设（风格 × 角色），JD 为可选项
   - 个性化题库生成：基于画像（+ JD/Gap 可选 + 面经库检索），输出结构化"考查包"（含追问地图与评判标尺）
   - 多轮面试对话：基于状态机中断与恢复机制，支持跨请求的长程会话
   - 动态追问：信号差检测，每题追问受控（1-3 次），追问地图在出题时预埋
   - 换题与结束：按预设"问答计划"推进，含反问环节，结束时机由计划而非墙钟决定
   - 面试官人设：风格 × 角色双维度，压力面作为风格正交叠加
   - 实战/教练双模式：实战模式面试中不评分（沉浸），教练模式侧边实时提示
   - 面试复盘报告：逐题回顾 + 改进范例 + 卡壳分析 + 可执行后续建议
   - 会话持久化与续面：跨请求、抗重启

2. **interview-knowledge-base（面试知识库）**
   - 个人面经库：面试复盘自动沉淀，per-user 私有，支持检索复用与成长对比
   - 公司/岗位面经库：混合冷启动（精选种子 + LLM 扩充 + UGC 替换），全局共享
   - 数据治理：来源标签（精选 / 生成 / UGC）+ 对用户透明展示
   - 混合检索：关键词 + 语义，服务出题增强与复盘对比

### 系统变更
- **LangGraph 状态机扩展**：引入 `interrupt` 中断与恢复机制（区别于现有简历解析、JD 匹配的"一次性流水线"子图），新增模拟面试子图（session_setup → interviewer ⇄ evaluator → debrief）
- **会话状态层新增**：引入持久化 checkpointer（独立存储文件），与现有业务数据层（SQLite 业务表）、内存对话记忆（MemorySaver）三层职责分离
- **State 扩展**：新增面试会话相关字段（会话元信息、问答计划、题库、transcript、累积评估、RAG 上下文、复盘产出等）
- **API 范式新增**：会话式 API（创建会话 / 提交答题 / 续面 / 获取复盘），答题端点采用多态响应
- **新依赖**：向量库与嵌入模型（用于面经库检索）
- **数据层新增**：面试会话表、复盘报告表、个人面经表、公司面经表

### 闭环调整说明
本变更**不实现"简历定制优化"环节**。闭环形态为：建立画像 → JD 匹配 → 模拟面试 → 复盘沉淀。JD 匹配产出的 Gap 清单直接作为模拟面试的"考查重点"输入之一。Gap 消费契约由本变更自行定义。

## Capabilities（能力清单）

### mock-interview（模拟面试）
**能力描述**：基于用户画像与（可选）JD 匹配结果，生成个性化面试题库，通过多轮对话模拟真实面试（含动态追问），面试结束后输出结构化复盘报告。

**核心流程**：
```
创建会话(选类型/档位/模式/人设/可选JD)
  → 出题(画像 [+JD/Gap] + 面经库检索 → 考查包题库 + 问答计划)
  → 多轮对话循环：
      interviewer 提问 → [中断等回答] → evaluator 评估
      → 决策(追问 / 下一题 / 进入反问 / 结束)
  → 复盘(逐题回顾 + 改进范例 + 卡壳 + 后续建议)
  → 沉淀(写入个人面经库)
```

**面试类型**：行为面 / 技术面 / 案例面 / 动机面 / 全流程 / 压力面（压力面为风格正交叠加）

**档位**：简短 / 正常 / 深度 / 全程（语义化，决定题量与深挖程度，不向用户暴露时间隐喻）

### interview-knowledge-base（面试知识库）
**能力描述**：维护个人面经库（per-user 私有，由面试复盘自动沉淀）与公司/岗位面经库（全局共享，混合冷启动），通过混合检索为模拟面试的出题与复盘提供个性化、真实化的弹药。

**核心行为**：
- 个人库：复盘时写入结构化面经条目；出题/复盘时按语义 + 关键词检索本人历史
- 公司库：混合冷启动建库（精选种子打底 + LLM 扩充长尾 + UGC 逐渐替换）；按目标公司 + 岗位检索真题增强真实感
- 治理：每条数据标注来源，检索优先级 精选 > UGC > 生成，且对用户透明

## Impact（影响分析）

### 用户体验影响
**正面影响**：
- 投递前/面试前获得可重复、低成本的"预演"环境，降低紧张、暴露弱点
- 动态追问 + 改进范例 + 卡壳分析，给出比"找朋友练"专业得多的结构化反馈
- 个人面经库越用越懂你，形成成长曲线，产生持续使用动机

**潜在风险**：
- 追问过于尖锐可能打击信心 → 缓解：人设风格可选（温和/轻松），实战模式默认不实时评分
- 公司面经库冷启动数据不全 → 缓解：来源标签透明，生成数据明确标注为"AI 拟题"
- 长程会话中途中断 → 缓解：checkpointer 持久化，支持续面

### 技术影响
**新机制引入**：
- LangGraph `interrupt` 中断与恢复（项目首次使用，区别于现有一次性子图）
- 持久化 checkpointer（项目首次引入会话状态层）
- 会话式 API + 多态响应（区别于现有一次性请求-响应 API）
- 向量库与混合检索（项目首次引入 RAG）

**依赖复用**：复用已有的 LLM 配置、结构化输出、重试机制、置信度范式、SQLAlchemy 基建、Vue 前端框架。

**性能影响**：
- 单轮面试交互（评估 + 决策 + 出下一题）：预计 5-10 秒
- 出题阶段（含 RAG 检索）：预计 8-15 秒
- 复盘生成：预计 10-20 秒
- MVP 采用同步 API + 前端分阶段提示（沿用现有模式）

**架构影响**：
- 引入项目第三种存储（会话状态层），与前两种（业务数据、对话记忆）分层
- 引入向量库作为第四类持久化（与关系库并列）
- 个人面经库的写入/检索构成跨能力的数据飞轮

### 开发影响
**工作量估算**：
- 后端：10-12 天（checkpointer 与 State 1.5 天、出题服务 2 天、interrupt 子图与 evaluator 2.5 天、会话式 API 1.5 天、复盘服务 1.5 天、RAG 双库 2 天、人设系统 1 天）
- 前端：5-6 天（会话配置、面试对话界面、双模式侧栏、复盘报告、面经库视图、历史）
- Prompt 调优：2-3 天（出题、追问决策、评估、复盘、人设）
- 测试与打磨：3 天（追问质量、档位节奏、RAG 召回、续面、边界）
- **总计：20-24 天**（建议分 5 个阶段递进交付，见 Timeline）

**技术风险**：
- interrupt 机制首次使用 → 缓解：先做最小 spike 验证可行性（de-risk）
- 追问质量不稳定 → 缓解：追问地图出题时预埋，evaluator 按图索骥而非自由发挥
- 公司库冷启动数据真实性 → 缓解：来源标签 + 透明展示 + 精选种子打底
- 向量检索召回不稳 → 缓解：关键词 + 语义混合检索

## Success Criteria（成功标准）

### 功能验收
- [ ] 能创建面试会话并配置（题型/档位/模式/人设，JD 可选）
- [ ] 无 JD 时也能基于画像 + 求职目标完成面试
- [ ] 题库基于画像个性化，且每题含追问地图与评判标尺
- [ ] 多轮对话流畅，支持基于回答的动态追问
- [ ] 追问受控（每题 1-3 次），追问到终点自动换题
- [ ] 按问答计划推进，含反问环节，计划执行完自动结束
- [ ] 实战/教练双模式行为正确（实战不实时评分，教练侧栏提示）
- [ ] 人设风格 × 角色生效，压力面可叠加
- [ ] 复盘报告含逐题回顾 + 改进范例 + 卡壳分析 + 可执行后续建议
- [ ] 会话可跨请求续面，后端重启不丢失
- [ ] 个人面经库复盘后自动沉淀，可检索复用
- [ ] 公司面经库冷启动完成，可检索增强出题
- [ ] 面经数据来源对用户透明展示

### 质量验收
- [ ] 追问有依据（基于预埋地图 + 信号差），非黑箱自由发挥
- [ ] 改进范例基于用户自身回答生成，非题库检索的标准答案
- [ ] 后续建议可执行（落到具体动作），非"加强 XX 能力"式空话
- [ ] LLM 失败有重试与友好降级
- [ ] 检索结果相关性合理（多样本验证）

### 用户体验验收
- [ ] 用户能在 1 分钟内配置并开始一场面试
- [ ] 面试节奏自然（破冰 → 主体深挖 → 反问），不像机械题单
- [ ] 复盘能明确指出"哪里不好、怎么改、下次怎么准备"
- [ ] 续面体验无缝（中断后回来能接着面）

## Timeline（时间线）

采用**分层点亮**策略——每个阶段都是可独立演示的完整闭环，做完即可录视频、讲故事。

**阶段 1：对话骨架（4 天）**
- checkpointer 持久化（SqliteSaver，独立文件）+ MockInterviewState 扩展
- interrupt 子图骨架（session_setup → interviewer ⇄ evaluator → debrief）
- 出题服务（画像 + 可选 JD/Gap，含 QuestionPackage 考查包结构）
- 信号差检测 + route_round 决策（追问/换题/结束）
- 基础复盘 + 会话式 API（创建/答题多态响应/续面/复盘）
- → 产出：能跑完一场文字面试，可演示（最小可讲故事版本）

**阶段 2：真实感与教学性（4 天）**
- 全题型支持（行为/技术/案例/动机/全流程）+ 压力面叠加
- 档位系统（简短/正常/深度/全程）+ 问答计划预生成
- 实战/教练双模式
- 详细复盘（改进范例对比 + 卡壳分析 + 可执行后续建议 + 能力雷达）
- 反问环节
- 人设系统（风格 × 角色）
- → 产出：体验"像真面试"，复盘有教学价值

**阶段 3：RAG 双库（4 天）**
- 向量库与嵌入接入（Chroma + BGE）
- 个人面经库（复盘沉淀 + 检索复用 + 成长对比）
- 公司面经库（混合冷启动 + 来源治理 + 检索增强出题）
- 混合检索（关键词 + 语义）
- → 产出：数据飞轮转起来（最强面试讲点）

**阶段 4：前端完整（5-6 天）**
- 会话配置页、面试对话界面、双模式侧栏、复盘报告、面经库视图、历史会话

**阶段 5：测试与打磨（3 天）**
- 追问质量多样本验证、档位节奏校准、RAG 召回评估、续面/边界处理、Prompt 调优

**总计：约 20-22 天**（阶段 1-3 为后端核心，阶段 4 前端可与阶段 3 部分并行）

> **语音增强（面试讲点级，非本变更范围）**：TTS 面试官声音 + STT 用户回答。文字对话层按"消息流"设计，语音作为可开关的输入输出层平滑接入，留作后续变更。

## 前置依赖

本变更的前置能力为 `user-profile`（画像）与 `jd-matching`（JD 匹配）。开工前需确认以下收敛（P0）：

- **画像侧**：真实简历样本验证经历细节（工作/项目描述）提取质量；画像完整度检查逻辑可用
- **JD 匹配侧**：真实 JD 样本验证四分类与 Gap 清单质量；匹配结果可持久化读取
- **共享**：确认 checkpointer 持久化方案（本变更阶段 1 落地）

前置未完全收敛时，本变更的阶段 1 可先行启动（interrupt spike、State 设计、Prompt 骨架均不依赖前置代码）。
