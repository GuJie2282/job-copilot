# Proposal: 面试节奏自主决策（evolve-interview-pacing）

## Why

模拟面试当前用一段写死的规则（`_decide`）控制面试节奏——何时追问、换题、进入反问、结束。规则只看计数器（追问次数、题目序号、是否已反问），不看回答语义，导致四类"不像真人面试官"的机械行为：

- 信号已补得差不多、只差一个边角，仍机械追问至次数上限；
- 候选人答得很水，仍凑满追问上限才换题；
- 候选人主动给出超出预埋信号的精彩内容，因"无缺失信号"直接换题，错失深挖机会；
- 已能判断候选人完全胜任或完全不胜任，仍必须走完题库全部题目。

真人面试官的节奏是语义驱动的：听懂了就往下走、有疑虑就追问、有料就深挖、心里有数就收尾。把节奏决策交给评估 LLM 能显著提升沉浸感与真实度——且评估 LLM 本就在每轮调用，决策可并入这次调用，几乎零额外延迟。

## What Changes

- 面试节奏（追问 / 换题 / 反问 / 结束）由评估 LLM 在每轮回答后**自主决策**，取代当前的计数器规则。
- 决策附带自然语言 `reason`，流入 transcript 与复盘，保留可解释性。
- 追问方向**可参考但不限于**出题时预埋的可挖掘点——LLM 可基于回答临场发现新的追问方向。
- 保留**防崩盘护栏**（工程护栏，非业务护栏）：最低/最高总轮数、单题最高追问次数、反问至多一次、死循环防护。护栏只兜底，不左右正常决策。
- 决策失败 / 超时 / 非法输出时降级回原规则决策，保证面试不中断。

## Capabilities

- `mock-interview`（MODIFIED）：动态追问、换题与结束两个 Requirement 改为 LLM 自主 + 护栏；ADDED「面试节奏自主决策与护栏」Requirement；原「追问按图索骥 SHALL NOT 自由发挥」「追问 3 次强制换题」两条硬约束废止，转为护栏下的自主决策。

## Impact

- **改动文件**：`graph/prompts.py`（评估 prompt 增 `action` / `action_reason` 输出与节奏指引）、`graph/nodes/mock_interview.py`（`_decide` 改读 LLM 决策 + 护栏校验，原计数器逻辑重构为 `_rule_decide_fallback` 保留；evaluator 存 `decision_reason`；interviewer probe 分支追问措辞语义扩展为可含临场方向）、复盘 prompt（纳入每轮 `decision_reason`）。
- **不动**：出题（question_generator）、interrupt 机制、checkpointer、API 层、前端；transcript entry 仅新增字段，向后兼容。
- **风险**：节奏不可完全复现（评估保持 temperature=0，真实感靠 prompt 指引塑造）；e2e 断言策略从「精确路径」改为「行为在合理范围」；护栏参数需实测调试。降级链路保证不崩。
- **面试讲点**：从「规则控节奏（可控可解释）」演进到「LLM 自主 + 护栏（真实且不崩）」，体现对 LLM 局限与工程权衡的理解——hybrid 是终点，而非直接放飞。
