# Proposal: 精修简历工作台化（evolve-resume-refine）

## Why

简历精修（路径 B）当前是一个**单列表单页**：上方显示评估，中间一块只读 Markdown 源码，底部一个「反馈」textarea。用户提一条反馈，后端同步改写整份 Markdown 再返回。这个形态有四个体验短板：

- **看不到成品**：精修全程只显示 Markdown 源码，用户改的是「代码」不是「简历」，无法直观感受排版与最终效果；只有定稿后才第一次看到 HTML 成品。
- **不能手动改**：用户即使只想改一个错别字、调一个词，也只能写成反馈等 AI 整份重生成，既慢又不可控。
- **黑盒改写**：AI 改写时没有任何过程可见，用户不知道 AI 为什么这么改、是否考虑了自己的诉求，信任感弱。
- **PDF 靠打印**：「导出 PDF」实为调用浏览器打印对话框，用户要手动选「另存为 PDF」，文件名随意、体验断裂，且不同浏览器排版不一致。

预览壳其实**已内置一套 contenteditable 编辑能力**（编辑按钮、原子级可编辑、技能 chip 增删、编辑后自动重排分页），但它是断头的——编辑产物只弹一个 textarea 供复制，既没回传精修流程，也没接进 AI 改写闭环。

本次把精修从「单列表单」升级为「**左右分栏的对话式工作台**」：左侧所见即所得地编辑简历成品，右侧与 AI 对话修改，改写过程透明（展示 AI 思考），定稿后一键导出真正的 PDF。

## What Changes

- **左右分栏工作台**：左侧渲染简历 HTML 成品并支持直接编辑文字（复用预览壳已有的 contenteditable 能力）；右侧为 AI 对话区，开场白给出操作指引（手动改 / 对话改 两种方式）。
- **手动编辑回流到单一真相源**：用户在左侧的直接编辑，精确回写到 Markdown 真相源的对应片段（不重建整份，避免未编辑字段丢失或变形）；AI 后续改写始终基于「含手动编辑的最新草稿」。
- **对话式改写**：用户以自然语言提出修改诉求，AI 回复包含「自然语言说明 + 改写后的简历」两部分；左侧随回复同步刷新。
- **改写过程透明**：精修改写期间增量展示 AI 的思考过程，与自然语言回复在视觉上区分（思考弱化色调、可折叠）。
- **PDF 服务端导出**：导出改为服务端将当前简历渲染为 A4 PDF 并以下载方式返回，取代客户端打印对话框；PDF 反映用户当前最新版本（含手动编辑）。

## Capabilities

- `resume-optimization`（MODIFIED）：「人机协同精修（路径 B）」改为对话式工作台（分栏、手动编辑、对话改写、思考展示）；「简历导出」的 PDF 导出改为服务端渲染下载；「API 响应格式」的精修响应改为流式 + 结构化。
- `resume-optimization`（ADDED）：「简历真相源与所见即所得编辑回写」（保证 Markdown 单一真相源、编辑精确局部回写）、「精修改写的思考过程与结构化回复」。

## Impact

- **前端改动**：`views/ResumeRefine.vue` 重构为左右分栏工作台（现单列表单作废）；`components/ResumePreview.vue` 增加编辑态与父页面双向通信（取代 iframe 内独立、断头的保存逻辑）；新增对话区组件（消息气泡、思考区、操作指引开场白）。
- **后端改动**：新增精修流式端点（SSE，取代同步 `/refine`），接 reasoning 公共层产出思考 + 结构化回复；新增手动编辑回写端点（局部 patch 当前草稿）；`resume_exporter.assemble_html` 与主题 `render_*` 为可编辑原子注入锚点；PDF 端点改为服务端渲染返回 `application/pdf`。
- **不动**：精修子图的 interrupt + checkpointer 长程会话范式（复用 mock-interview 同构）、画像追问、定稿落库逻辑、生成阶段（路径 A）。
- **依赖**：复用 add-reasoning-display 的 `stream_chat_with_reasoning` 公共层；承接 add-streaming-pipeline 中尚未完成的 refine 流式部分，不重复立项。
- **风险**：HTML 编辑回写的保真度（局部回写需覆盖所有可编辑原子与字段，否则手改内容回写时丢失）；服务端 PDF 渲染依赖额外浏览器二进制（体积与部署成本）；精修结构化输出（自然语言 + 简历）的流式切分稳定性。
- **面试讲点**：①复用 mock-interview 长程会话范式做对话式精修；②「单一真相源 + 锚点局部回写」化解「所见即所得编辑」与「AI 改写」的双源冲突——避开双源真相的经典坑；③reasoning 透明化从生成延伸到精修；④服务端端到端精确导出 PDF（呼应 exporter 早先埋下的「精确页数待浏览器渲染」伏笔）。
