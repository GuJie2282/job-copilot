# Proposal: 首页引导链路进化 + 全站 CTA 可见性

## Why（为什么需要）

两个独立但同源的前端体验痛点——都让用户"用得不顺"：

### 痛点 1：首页链路条"卡在 JD 匹配"，引导失真
首页求职链路条（画像→JD匹配→简历优化→模拟面试）本意是**新用户引导**，但当前只拉了画像 + 匹配两个数据源，stage3/4 硬编码 `todo`。后果：用户即便做完了简历优化、练过模拟面试，链路条也永远停在"JD 匹配"那一步——引导与真实进度脱节，用户感受不到自己走过了多远。

### 痛点 2：底部功能按钮被长内容推出视口，用户看漏
配置/输入型页面（尤其「模拟面试设置」）内容长、主 CTA 在最底部，用户填配置时根本看不到「开始面试」按钮，要一路滚到底才发现。结果型页面（JD 匹配 / 简历优化的结果区）的次级 CTA（「据此生成简历」「进入精修」）也埋在长结果深处，同样易被看漏。

## What Changes（做什么变更）

### home-onboarding（首页引导链路）
- 链路条按**真实完成度链式推进**（拉全 4 个数据源：画像 / 匹配 / 简历 / 面试）
- **严格完成定义**：匹配要有分、简历要 finalized、面试要 finished
- 全链路完成 → **祝贺态**（隐藏「下一步」卡，显示祝贺文案 + 指引 CTA）
- 动效统一：done 段连线**流光** + active 节点 **pulse**（每个环节都有动效）
- 链路条整体**放大**（圆点 / 字号 / 连线 / 间距）

### page-cta-visibility（全站 CTA 可见性）
- 配置/输入型页面：主 CTA 改 **sticky 底部 bar**（始终可见 + 配置摘要）
- 结果型页面：次级 CTA **上移 / 双 CTA**（结果顶部也放）
- 详情型页面：操作按钮 **sticky 或顶部**

## Capabilities
- `home-onboarding`（新增）
- `page-cta-visibility`（新增）

## Impact
- 受影响页面：Home / InterviewSetup / JdMatcher / ResumeOptimizer / Profile
- 纯前端改动（各页 .vue + 可能抽一个 `StickyActionBar` 共用组件）
- 不影响后端
