# Proposal: 简历解析与个人画像建立

## Why（为什么需要）

### 当前痛点
用户第一次使用求职 Copilot 时，系统对用户一无所知，无法提供个性化的 JD 匹配、简历优化或模拟面试服务。用户需要重复提供基本信息，体验割裂。

### 产品价值
**简历解析与个人画像建立**是整个求职 Copilot 的**第一步核心能力**：

1. **一次性投入，长期受益**：用户只需上传一次简历，后续所有功能（JD 匹配、简历优化、模拟面试）都能基于画像提供个性化服务
2. **提升后续能力质量**：个人画像包含教育背景、工作经历、技能、项目经验，是 JD 匹配和简历优化的基础数据
3. **降低使用门槛**：自动解析简历比手动填写表单更友好，减少用户流失
4. **产品差异化**：市场上大多数产品只做单点功能（只改简历或只模拟面试），缺乏"画像驱动的全链路"能力

### 战略定位
作为求职 Copilot 的**入口能力**，简历解析的体验直接影响用户对整个产品的第一印象。必须做到：
- **准确**：解析结果可靠，用户信任
- **友好**：多种输入方式，适应不同场景
- **透明**：置信度展示，用户知道哪些信息可能需要修正

## What Changes（做什么变更）

### 新增能力
1. **resume-parsing（简历解析）**
   - 支持文件上传：PDF（非扫描）、docx
   - 支持文本粘贴：整份简历文本
   - 支持手动填写：无简历用户可手动填写表单
   - 示例简历测试：提供示例简历供用户快速测试
   - 多层防御：文件检测 → 文本提取 → 质量评估 → LLM 容错解析
   - 降级策略：解析失败时引导用户使用备选方案
   - 进度指示：分阶段显示解析进度（上传→解析→提取→计算）

2. **user-profile（个人画像）**
   - 结构化数据：基础信息、教育、工作、技能、项目、求职目标
   - 置信度评分：每个字段显示提取准确度（百分比）
   - 用户修正：解析结果可手动编辑
   - 画像导出：支持导出 JSON、Markdown 格式
   - 画像管理：支持删除、重新上传
   - 持久化存储：画像保存供后续功能使用

3. **user-onboarding（用户引导）**
   - 上传前引导：说明支持的格式、示例链接
   - 完成后引导：展示后续功能（JD 匹配、简历优化、模拟面试）
   - 帮助文档：常见问题解答

## Capabilities（能力清单）

### resume-parsing（简历解析）
**能力描述**：从用户上传的文件或粘贴的文本中提取简历内容，并解析成结构化个人画像。

**核心功能**：
- 文件上传：支持 PDF（非扫描件）和 docx 格式
- 文本粘贴：支持直接粘贴简历文本
- 文件解析：使用 pdfplumber 和 python-docx 提取文本
- 质量检测：评估提取文本的质量（长度、中文比例、结构完整性）
- LLM 提取：调用 LLM 从文本中提取结构化画像
- 容错解析：对低质量文本使用增强 Prompt
- 置信度计算：评估每个字段的提取准确度

**降级策略**：
- 扫描件 PDF：引导用户复制粘贴或手动填写
- 文件损坏/加密：提示用户检查文件
- 解析失败：提供文本粘贴和手动填写两种备选

### user-profile（个人画像）
**能力描述**：存储和管理用户的个人画像，供后续能力（JD 匹配、简历优化、模拟面试）使用。

**数据结构**：
- 基础信息：姓名、联系方式、邮箱、所在地
- 教育背景：学校、学历、专业、毕业年份、GPA
- 工作经历：公司、职位、时间、职责、成就
- 技能：技术技能、软技能、语言能力
- 项目经验：项目名称、角色、描述、成果
- 求职目标：目标岗位、目标公司、地点偏好、薪资范围、行业

**功能**：
- 画像展示：以友好的界面展示结构化画像
- 置信度显示：每个字段显示提取准确度（百分比）
- 画像编辑：用户可手动修正或补充信息
- 画像存储：持久化存储到数据库（MVP 用内存，v1 用 SQLite）
- 画像更新：支持用户后续更新画像

## Impact（影响分析）

### 用户体验影响
**正面影响**：
- 首次使用流程更顺畅：上传简历 → 看到画像 → 开始使用其他功能
- 多种输入方式适应不同场景：有文件用文件，没文件复制粘贴
- 透明度提升：用户知道哪些信息准确，哪些需要确认

**潜在风险**：
- 如果解析准确率低（<70%），用户可能失去信任
- 如果上传失败，用户可能放弃使用

**缓解措施**：
- 多层防御 + 降级策略确保至少有一种方式成功
- 文本预览让用户可以修正后再解析
- 友好的错误提示和引导

### 技术影响
**依赖新增**：
- PDF 解析库：pdfplumber、PyPDF2
- Word 解析库：python-docx
- 文件处理：临时文件存储和清理

**性能影响**：
- 文件解析增加响应时间（预计 2-5 秒）
- LLM 提取增加响应时间（预计 5-10 秒）
- MVP 阶段使用同步 API，用户体验可接受

**架构影响**：
- LangGraph 状态机复杂度增加（新增 6 个节点）
- State 字段增加（需要持久化策略）
- 与后续功能的集成（JD 匹配、简历优化依赖画像）

### 开发影响
**工作量估算**：
- 后端开发：3-4 天（文件解析、LangGraph 节点、API、重试机制、超时处理）
- 前端开发：4-5 天（文件上传、文本粘贴、手动表单、进度指示、画像展示/编辑、导出功能）
- Prompt 调优：1-2 天（提高解析准确率、重试策略）
- 测试与打磨：2-3 天（真实简历测试、边界情况处理、用户体验优化）
- **总计：11-12 天**

**技术风险**：
- PDF 解析准确率可能不稳定（缓解：多解析器备选 + 质量检测 + 第三解析器）
- LLM 提取可能遗漏字段（缓解：容错 Prompt + 用户修正 + 重试机制）
- 文件处理可能出错（缓解：降级策略 + 友好提示 + 定时清理）
- 超时问题（缓解：超时处理 + 保留已提取文本）
