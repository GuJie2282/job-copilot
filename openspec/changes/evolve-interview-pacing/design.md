# Design: 面试节奏自主决策

## 背景

当前节奏由 [`_decide()`](backend/src/graph/nodes/mock_interview.py#L346) 硬编码：`probe_count < probing_limit(3)` 且有缺失信号 → probe；否则按 `idx` 顺序走 next / enter_qa / end。LLM 只产出"追什么方向 + 怎么说"（`miss_probe_map` + `next_probe_followup`），"要不要追 / 换 / 结束"由规则定。

本变更换主：节奏交给评估 LLM，规则退居护栏。

---

## 决策

### 决策 1：节奏决策并入评估 LLM，不新增往返

评估 LLM 每轮已在调用。在其输出 JSON 增 `action`（probe | next | enter_qa | end）+ `action_reason`（一句理由）字段。`_decide` 改为读 LLM 的 action，经护栏校验后采用。

**理由**：延续项目"合并 LLM、省往返"的优化方向（评估 + 追问措辞此前已合并）。零额外延迟、零额外成本。评估与节奏决策本就基于同一份"回答 vs 标尺"的判断，天然耦合，合并语义自洽。

### 决策 2：护栏分两层——业务护栏松绑，工程护栏保留

用户明确"提前结束、连追多轮都能接受"，故**业务护栏全撤**：不再硬限"追问 3 次强制换题"、不再要求"题库走完才结束"——LLM 可随时结束、可连追多轮。

但**工程护栏必须留**（防产品崩盘，与业务无关）：

| 护栏 | 作用 | 默认值 |
|------|------|--------|
| 最低总轮数 | 防 LLM 开场就 end（空面试） | ≥ 1 |
| 单题最高追问 | 防单题钻牛角尖死循环 | 5 |
| 反问至多一次 | 防反复 enter_qa | 1 |
| 最高总轮数 | 防永不结束 | 题库量 + 单题追问缓冲 |

护栏只在 LLM 决策越界时介入，正常情况下完全遵循 LLM。

**理由**：业务护栏（节奏感）交给 LLM 更像真人；工程护栏（不死不崩）是产品底线，不能交。区分二者是本变更的核心工程判断，也是面试主讲点。

### 决策 3：追问方向"可参考但不限于"预埋可挖掘点

LLM 决定 probe 时，追问方向：

- **优先**参考该题 `probing_points`（弹药库）与缺失信号；
- **允许**基于回答临场发现的新方向（候选人主动提到、值得深挖的点）。

即从"按图索骥、禁止自由发挥"松绑为"图为弹药、临场可发挥"。

**理由**：候选人的精彩回答常超出预埋信号，禁止自由发挥会浪费深挖机会（痛点场景③）。但保留弹药库作为安全网，避免追问完全脱纲。`next_probe_followup` 字段语义从"按缺失信号生成的措辞"扩展为"LLM 自主决定的追问措辞（含临场方向）"。

### 决策 4：评估保持 temperature=0，真实感靠 prompt 指引

评估的"信号检测 + 评分 + 理由"需要稳定可复现（便于回归测试与复盘一致性）；节奏决策的"轻随机像真人"用 prompt 里"像真人面试官"的节奏指引来塑造，而非靠温度噪声。

**折中结论**：评估 LLM 保持 `temperature=0`。由于 prompt 给出了完整的信号评估，LLM 在明确信号下的 action 选择本就高度收敛，0 温度的"准确定性"已足够自然，且换来可复现与可回归。若后续实测发现节奏过于机械（同类回答永远走同一路径），再考虑对决策单开一次轻温度 LLM——默认不增加往返。

**理由**：优先保评估可解释性与测试可回归；真实感通过 prompt 指引塑造更可控（温度噪声是不可解释的随机，prompt 指引是可调的"节奏感"）。

### 决策 5：决策理由流入复盘，保解释性

LLM 的 `action_reason` 存入 transcript entry（`decision_reason` 字段），并喂入复盘 prompt。复盘的逐题回顾可呈现"这轮为什么追问 / 换题 / 结束"。

**理由**：用户已确认接受"LLM 觉得答够了"这类软解释。解释性从"缺 X 信号（硬）"升级为"LLM 节奏理由（软但可读）"，仍满足复盘的可解释诉求。

### 决策 6：降级——决策失败回退规则（保守追问）

LLM 决策失败 / 超时 / 返回非法 action：

- `_decide` 回退到**原计数器规则**（`_rule_decide_fallback`，保留不删）；
- **评估 LLM 整体失败**时，降级返回 `miss_signals=ideal_signals` + `miss_probe_map`（按可挖掘点映射），action=None 交规则 fallback——看到 miss 非空 → probe（保守追问，受 probing_limit 上限保护）。**评估失败 ≠ 回答充分**：偶发超时时空洞回答仍被追问一次（interviewer 模板降级用 miss_probe_map 生成"能具体讲讲——{点}"）。
- 评估 `max_retries=1→0`：偶发超时即降级（20s 上限），不拖到 43s；因降级已保守追问，失败不再等于"不追问"，减重试换更低延迟是划算的。

**理由**：原降级"假设充分不追问"在评估偶发超时时导致"完全不追问"（实测诊断：score=70/action=None/miss_signals=[]）。保守追问（miss=ideal）让偶发失败也能追问，配合 max_retries=0 快速降级，既不拖延迟也不丢追问。保留 `_rule_decide_fallback` 仍作规则通道。

### 决策 7：测试策略——断言行为范围，不断言精确路径

节奏自主后，测试调整：

- **单测**：`_decide` 拆"LLM action 采纳路径"与"规则 fallback 路径"两组分别断言；护栏单测构造越界 action（开场 end、连追越界、反问重复、超总上限）断言纠正。
- **e2e**：断言"面试在 [最低, 最高] 轮数内正常结束、transcript 完整、复盘生成"，不断言具体每轮 action。

**理由**：节奏自主性是特性，测试应验证"自主但不崩"，而非锁死路径。

---

## 不做

- 不引入多 Agent / 角色扮演框架（复杂度不匹配个人作品集项目）。
- 不把出题、信号评估、复盘也交给 LLM 自由化——本次只松绑"节奏决策"这一段。
- 不增加 LLM 往返（决策并入评估，见决策 1）。
- 不为节奏单开轻温度 LLM（见决策 4，留口子但默认不做）。
