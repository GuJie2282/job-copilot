## Why

当前认证系统（backend-auth-and-token-refresh）实现存在多个严重问题：

1. **数据一致性风险**：缺少数据库事务保护，多步操作（验证码标记、用户创建、Token生成）在失败时会导致数据不一致。例如：验证码被标记为已使用但用户创建失败，导致验证码被浪费。

2. **异常处理缺失**：数据库操作、外部服务调用等缺少异常捕获和回滚机制，系统健壮性不足。

3. **边界情况处理不全**：登录时密码错误、注册时账号已存在、Token 刷新失败等常见场景没有友好的错误提示和处理逻辑。

4. **前后端接口不匹配**：字段命名不一致（如 `refreshToken` vs `refresh_token`），导致请求失败。

5. **缺少测试保障**：核心认证流程没有单元测试，重构和优化风险高。

这些问题直接影响用户体验、系统稳定性和数据安全。必须在扩展业务功能之前修复，否则技术债务会快速累积。

## What Changes

### 核心优化

- **数据库事务管理**：为所有涉及多步操作的认证流程添加事务保护（注册、登录、Token刷新）
- **统一错误处理**：建立错误码体系，提供详细、友好的错误消息和操作指引
- **结构化日志**：添加关键路径的结构化日志，便于问题排查和监控
- **边界情况覆盖**：完善所有边界情况的处理逻辑（10+ 注册场景、6+ 登录场景、4+ Token刷新场景）
- **API 契约修复**：统一前后端字段命名规范，确保接口匹配

### 新增能力

- **错误响应标准**：统一的错误响应格式，包含错误码、用户友好消息、建议操作
- **验证码状态区分**：区分验证码错误、过期、已使用三种状态，提供针对性提示
- **Token刷新重试机制**：前端 Token 刷新队列，避免并发刷新请求

### 测试覆盖

- **单元测试**：覆盖核心认证逻辑（密码哈希、Token生成、验证码验证）
- **集成测试**：测试完整认证流程（注册→登录→刷新→登出）
- **边界测试**：测试所有边界情况和异常场景
- **事务回滚测试**：验证失败场景下的数据回滚

### **BREAKING** 变更

- **错误响应格式变更**：从简单的 `detail` 字符串改为结构化错误对象（含 `code`、`message`、`action` 字段）
- **刷新Token请求字段**：后端将统一使用下划线命名（`refresh_token`），前端需要调整

## Capabilities

### New Capabilities

- `error-handling`: 统一的错误处理规范，包括错误码体系、错误消息设计、异常捕获机制
- `transaction-management`: 数据库事务管理规范，明确事务边界、回滚策略、隔离级别
- `structured-logging`: 结构化日志规范，包括日志级别、关键路径覆盖、敏感信息脱敏
- `auth-testing`: 认证模块测试规范，包括单元测试、集成测试、边界测试策略

### Modified Capabilities

- `user-registration`: 注册流程 REQUIREMENTS 变更
  - 新增：事务原子性要求
  - 新增：边界情况处理要求
  - 新增：友好错误消息要求

- `user-login`: 登录流程 REQUIREMENTS 变更
  - 新增：密码错误提示优化（区分用户不存在和密码错误，日志记录）
  - 新增：账户禁用状态处理
  - 新增：登录失败次数限制（未来扩展）

- `token-refresh`: Token刷新流程 REQUIREMENTS 变更
  - 新增：刷新失败重试机制
  - 新增：并发刷新请求处理
  - 新增：Token轮换原子性保证

## Impact

### 受影响的代码

**后端：**
- `backend/src/services/auth_service.py` - 添加事务管理、异常处理、边界检查
- `backend/src/api/auth.py` - 统一错误响应格式、添加详细日志
- `backend/src/services/code_service.py` - 优化验证码验证逻辑、区分错误类型
- `backend/src/core/security.py` - 添加结构化日志

**前端：**
- `web/src/api/auth.ts` - 调整字段命名、适配新的错误响应格式
- `web/src/api/client.ts` - 优化Token刷新重试逻辑
- `web/src/stores/user.ts` - 添加错误处理逻辑

### 新增依赖

**后端：**
- `pytest` - 单元测试框架
- `pytest-asyncio` - 异步测试支持
- `pytest-cov` - 测试覆盖率
- `httpx` - 异步HTTP客户端（用于测试API）

### API 变更

- **错误响应格式**：所有 API 端点的错误响应从字符串改为结构化对象
- **Token刷新字段**：`refreshToken` → `refresh_token`（建议后端统一使用下划线命名）

### 数据库变更

- 无结构变更，仅添加事务使用
- 未来可考虑：添加 `login_attempts` 表记录登录失败次数

### 兼容性

- **向后兼容**：新的错误响应格式保持向后兼容，前端可逐步迁移
- **前端迁移**：需要适配新的错误响应格式和字段命名
